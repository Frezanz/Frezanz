# 📐 HOW I BUILD

```text
               START WITH WHY
                     │
                     ▼
                MODEL SYSTEM
                     │
                     ▼
               FIND PRIMITIVES
                     │
                     ▼
              BUILD SMALLEST CORE
                     │
                     ▼
                 BREAK / TEST
                     │
                     ▼
               REBUILD BETTER
                     │
                     └──────────→ repeat
```

**01 — Understand the primitive.** If an abstraction is important, I want to know what is underneath it.

**02 — Build before over-planning.** A small working system teaches more than architecture that never runs.

**03 — Keep the mechanism visible.** Black boxes are useful. Understanding them is better.

**04 — Treat failure as data.** A broken build is often a measurement of a wrong assumption.

**05 — Connect disciplines.** Math → algorithms → models → software → interfaces → users.
